# sgpt 0.6.0 设计与实现说明

本文档是 0.6.0 的权威版本说明，合并并取代原有 fix、test、review remediation 和 architecture deepening 计划。它记录最终产品语义、架构、协议、资源限制、测试 seam、兼容性和手工验证要求；用户使用方法见 [`README.md`](../README.md)。

长期架构决策仍由 ADR 单独记录：

- [ADR-0001：一棵 Projection Tree 使用一个 Origin Relay](adr/0001-one-origin-relay-per-projection-tree.md)
- [ADR-0002：Origin Relay 持有 projected Conversations](adr/0002-origin-relay-owns-projected-conversations.md)

## 版本目标

0.6.0 将 0.5.x 中分散的 Conversation、远端 history、Provider Request 选择和 SSH policy 收敛为明确的深 module，并修复资源上限、并发、持久化和声明一致性问题：

- Conversation 只包含完整 Turns，并在逻辑或物理压缩后保留最新成功 Turn。
- Input Anchors、近期 Turns 和 Provider Request 使用明确且有界的保留规则。
- Local Shell Session 的成功 Turn 是一个事务；持久化失败不替换 current、不输出回答。
- 一个 Origin Relay 统一持有整棵 Projection Tree 的 projected Conversations。
- 一个 Origin Relay 支持多级和分支 Tunnel Hops，同时保持各 Shell Session Conversation 独立。
- 首跳与 nested Tunnel Hop 使用同一个 SSH policy 权威来源。
- stdin、Provider Request/Response、history、relay body 和 `ssh -G` 输出在资源消耗阶段执行上限。
- 测试通过 module interface 或真实外部 seam 验证行为，不依赖私有 map、文件布局或脚本 substring。

## 非目标

- 不支持 relay federation；一棵 Projection Tree 始终只有一个 Origin Relay。
- 不持久化 Projected Conversations；Tunnel 退出后不跨重连保留。
- 不向远端安装 Rust binary，也不向远端发送 API Key 或 Provider 配置。
- 不增加旧 relay protocol 兼容层；运行中的 0.5.x Tunnel 必须重连。
- 不增加 Conversation 列表、切换功能或流式输出。
- 不支持原生 Windows Shell。
- 不引入通用 repository、event bus、dependency injection framework、插件系统或仅为测试存在的公共 trait。

## 领域语言与核心不变量

领域术语以 [`CONTEXT.md`](../CONTEXT.md) 为准。

### Shell Session 与 Conversation

- 一个 Local 或 Projected Shell Session 最多拥有一个 current Conversation。
- Conversation 是完整 Turns 的有序集合；Turn 是一次 user input 与一次成功 assistant response。
- 普通请求创建新 Conversation，只在首个 Turn commit 并持久化成功后替换 current。
- `continue` 只更新已有 current Conversation；不存在 current 时明确失败。
- Provider 成功但 Turn commit 或持久化失败时，不输出回答、不替换 current。
- Input Anchor 来自包含非空 stdin 的历史 user input，保留 instruction、stdin 和 timestamp，不保留旧 assistant response。

### Projection Tree

- 每个根 `sgpt tunnel ssh` 创建一个 Origin Relay 和一棵独立 Projection Tree。
- 每个 Tunnel Hop 创建独立 Projected Shell Session。
- Nested Tunnel Hop 复用同一个 Origin Relay，不创建或联邦新 relay。
- Origin Relay 是所有 Projected Shell Sessions 的 Conversation 唯一权威来源。
- 远端只发送 identity、new/continue intent、当前结构化输入和当前主机 ContextBlock。
- Parent 和 child 的 Conversations 相互独立；删除 parent 时递归删除 descendants。

### Projected Shell Session lifecycle

```text
Pending --activate--> Active --unregister--> Closing --> Removed
    \--60s expiry-------------------------------------> Removed
```

- SSH preparation 创建 Pending，并占用 Session 名额，但不创建 Conversation。
- bootstrap 成功后幂等 activate。
- 只有 Active Session 可以 ask 或创建 child Tunnel Hop。
- Active Session 不设 idle TTL。
- Pending 60 秒未 activate 会被释放。
- 无 in-flight lease 的 unregister 立即删除；有 lease 时进入 Closing，最后一个匹配 lease 完成后删除。
- 同一 Projected Shell Session 最多一个有效 lease。
- stale lease 不能提交 Conversation，也不能释放新 lease。
- request future 被取消时只释放自己的 lease。

### Request idempotency

- `request_id` 是 Shell Session 内的幂等键。
- Turn 保存 request ID 和请求摘要。
- 同 ID、同摘要返回已提交回答，不再次调用 Provider。
- 同 ID、不同摘要返回 conflict。
- 远端 shell 仅对 curl transport failure 做一次重试，并复用同一 request 文件和 ID。
- HTTP 或 Provider 失败不会自动换 ID 重试。

## 最终 module 结构

```text
src/
  conversation.rs
  projection/
    mod.rs
  relay/
    mod.rs
  local_session/
    mod.rs
    history.rs
  ai/
    mod.rs
    request.rs
  tunnel/
    bootstrap.rs
    ssh/
      mod.rs
      policy.rs
      process.rs
```

### Conversation module

`src/conversation.rs` 不依赖文件系统或 HTTP，拥有：

- `Conversation`、`Turn`、`UserInput`、`AssistantResponse` 和 `InputAnchor`。
- Turn commit 和 request ID 幂等规则。
- 逻辑高低水位压缩。
- 为外部物理限制移除最旧完整 Turn 的领域操作。
- Anchor 提取、数量/字节限制、UTF-8 安全首尾截断和时间顺序。
- 历史加载后的 Anchor 确定性规范化。

文件 persistence 不重写 retention 规则；AI request construction 不拥有长期 Conversation 保留规则。

### Projection Tree state module

`src/projection/mod.rs` 集中拥有：

- membership、parent/child 和 Session limit。
- Pending/Active/Closing/Removed 转换与 pending expiry。
- lease ID 分配、matching commit/abandon 和 cancellation cleanup。
- Projected Conversation selection、replacement、replay 和 conflict。
- 稳定 snapshot 测试 interface。

该 module 不依赖 Axum。`src/relay/mod.rs` 只负责 HTTP decoding、鉴权、route body limit、领域 outcome 到 HTTP 的映射、Provider 调用和全局 permit。Provider 调用期间不持有 Projection Tree mutex。

### Local Shell Session module

`src/local_session/mod.rs` 对 command dispatcher 暴露完整事务：

```text
LocalShellSession::execute(LocalRequest) -> answer
```

`LocalRequest` 使用受限 mode enum，并包含 ContextBlock 和 UserInput。事务顺序为：

1. resolve 当前 Local Shell Session；
2. acquire Session lock；
3. 选择 new/continue Conversation；
4. 调用 Provider；
5. 构造并 commit 完整 Turn；
6. 持久化 committed Conversation；
7. new 模式在持久化成功后替换 current；
8. 返回可发布 answer。

`main.rs` 只在事务成功返回后写 stdout。`src/local_session/history.rs` 是私有文件 adapter，负责 version 1/2 parse、append、atomic rewrite、current、lock、权限和物理大小检查。

### AI request construction module

`OpenAiClient::ask(ContextBlock, Conversation, UserInput)` 是调用方 interface。`src/ai/request.rs` 私有实现集中拥有：

- recent Turn soft-budget selection；
- Anchor 与最终 selected Turns 的去重；
- 最新完整 Turn → Input Anchors → 更多连续近期 Turns的优先级；
- system/context/current input rendering；
- OpenAI-compatible messages；
- 实际 JSON 序列化字节限制。

不存在跨 module 的 `RequestContext` 或公开候选 vectors。序列化错误直接传播，不会被转换为虚假的大小超限。

### SSH policy 与 adapters

`src/tunnel/ssh/policy.rs` 是 SSH policy 的唯一权威来源，拥有：

- controlled options；
- prohibited execution/query/control modes；
- option arity 和 attached/separated forms；
- destination 与附加 remote command validation；
- normalized effective config forwarding listener parser；
- `SGPT_PORT` conflict 规则；
- 只允许内部构造的 validated args。

存在两个真实 adapters：

1. `process.rs`：本机 Rust process adapter，执行 `ssh -G` 和最终 SSH，负责有界并发读取、kill/wait/reap 和退出状态。
2. `bootstrap.rs`：远端 POSIX shell adapter，在中间主机执行 nested `ssh -G` 和最终 SSH。

bootstrap 的 controlled argv 和 prohibited mode validator 由 Rust policy constants 确定性生成，不在 shell 中维护第二份手写表。用户 argv 始终通过 `"$@"` 传递，不使用 `eval`。Nested preflight 的 FIFO readers 和 `ssh -G` 被封装在前台子 shell 中，避免向交互式 Bash 泄漏 job-control 通知。

## Provider Request 与 Conversation 保留

### Input Anchor invariant

Conversation 内 Anchors 始终同时满足：

- 总正文不超过 `150 KiB`；
- 数量不超过 10；
- 超限时保留最初 Anchor 和最近若干 Anchors；
- 最初 Anchor 最多使用一半总预算；
- 单个 Anchor 超限时保留 UTF-8 安全首尾，并插入 `[history truncated]`；
- 输出保持时间顺序。

历史 version 2 中合法但超过新 Anchor invariant 的数据在加载时确定性规范化，并在下一次成功保存时原子重写。

### Provider Request selection

必需内容包括内置 system prompt、ContextBlock、附加 system prompt 和当前 user input。必需内容自身超过 `1 MiB` 时：

- 不调用 Provider；
- 不修改 Conversation；
- 不输出回答。

可选内容按顺序分配：

1. 最新完整 Turn；
2. Input Anchors；
3. 更多连续近期 Turns suffix。

近期历史最多 10 个完整 Turns，软预算 `200 KiB` UTF-8。Anchors 在最终发送前对全部 selected Turns 去重。最终硬限制按实际 JSON 序列化字节执行，包含 escaping 和多字节 UTF-8；任何候选失败都不会产生半个 Turn。

### Logical 与 physical compaction

- Conversation 逻辑高水位为 `2 MiB`。
- 超限后压缩到约 `1.5 MiB`，始终保留最新完整 Turn。
- 被移除且含 stdin 的 Turn 转换为 Input Anchor。
- history version 2 JSONL 物理安全上限为 `16 MiB`。
- 接近物理上限时，history adapter 调用 Conversation 的完整 Turn 移除操作，直到实际序列化结果降到安全水位，再 atomic rewrite。
- 最新单个 Turn 自身无法持久化时明确失败，并保持原文件和 current 不变。

## Local history version 2

每个成功 Turn 是一条完整 JSONL record；独立保留的 Anchor 使用 `input_anchor` record。记录包含 `version: 2` 和 `kind`。

结构化 user input 保存：

- instruction；
- stdin；
- timestamp。

Turn 另外保存 request ID、request digest、assistant content 和 timestamp。

Version 1 迁移：

- 只接受相邻 `user + assistant` 完整配对。
- 使用 `stdin_bytes` 从旧 user content 尾部恢复 stdin，剩余部分恢复 instruction。
- 无法可靠配对、拆分或解析时明确报错，源文件保持不变。
- 第一次成功写入时使用临时文件和 rename 原子迁移为 version 2。
- 不存在把损坏数据静默当成空 Conversation 的 fallback。

## Origin Relay protocol

Origin Relay 只监听 loopback，并使用 64 字符随机 tree token 的 Bearer authentication。Projected Shell Session ID 和 request ID 是十六进制随机 ID。

### Ask envelope

Remote Ask Envelope 包含：

- `request_id`；
- `session_id`；
- `mode: new | continue`；
- 结构化 instruction/stdin；
- ContextBlock。

Envelope 不包含 history、current Conversation 或 Provider 配置。Origin Relay 重新验证字段，并在本地构造 Provider Request。

### Routes

```text
POST /v1/ask
POST /v1/session/activate
POST /v1/session/unregister
POST /v1/session/cancel
POST /v1/tunnel/prepare
GET  /v1/bootstrap/sh
```

读取阶段和 handler 协议校验都执行 route-local body limit：

- Ask：`4 MiB + 1` reader gate，名义正文上限 `4 MiB`。
- Tunnel Prepare：`512 KiB + 1` reader gate，名义正文上限 `512 KiB`。
- Session control：`64 KiB + 1` reader gate，名义正文上限 `64 KiB`。

超过名义上限返回 `413`，且不会修改 Session 或 Conversation 状态。

### Session 与 Provider concurrency

- `SGPT_MAX_PROJECTED_SESSIONS`：`1..=256`，默认 `64`。
- `SGPT_MAX_CONCURRENT_REQUESTS`：`1..=16`，默认 `4`。
- 每个 Projected Shell Session 同时最多一个请求。
- 不同 Sessions 可以并发。
- Origin Relay 使用全局 semaphore 限制 Provider 并发。
- 达到上限立即返回明确错误，不无限排队、不静默淘汰 Conversation。

## Remote bootstrap

Stage 1 bootstrap 通过 SSH remote command 以 base64 传输并由远端 `/bin/sh` 执行。它负责：

- 检查远端依赖；
- 创建权限受限的临时 runtime/session 目录；
- activate Projected Shell Session；
- 注入 `sgpt` shell function；
- 有界读取 stdin；
- 收集 cwd、uname、shell、`/etc/os-release` 和 `sw_vers`；
- ask/retry/unregister/cancel；
- 执行 nested Tunnel Hop；
- 清理临时文件。

远端依赖：

```text
sh curl jq base64 od tr mktemp mkfifo cat wc head id mkdir chmod rm uname
```

Nested Tunnel Hop 额外需要 `ssh`。缺失依赖会输出稳定诊断 `sgpt remote dependency missing: <name>`。远端不保存 Conversation、history、current 或 API Key。

Shell startup：

- Bash：`/etc/profile` → `.bash_profile` / `.bash_login` / `.profile` 中最高优先级存在者 → `.bashrc` → sgpt injection。
- Zsh：使用临时 `ZDOTDIR` 转接真实 `.zshenv`、`.zprofile`、`.zshrc`、`.zlogin`。
- Fish：先 source 真实 `$HOME/.config/fish/config.fish`，再注入 sgpt function。
- POSIX sh：加载临时 rc 和 cleanup trap。

Activation 只接受 HTTP 2xx；404/409/500 或 transport failure 在进入交互 Shell 前 fail fast。Unregister 是短超时 best-effort，不能覆盖原始退出状态。

## SSH policy

每一跳都在实际执行 SSH 的主机上运行 `ssh -G`，让 OpenSSH 负责：

- 用户和系统 `ssh_config`；
- `Host`、`Match`、`Include`；
- alias、变量展开和配置优先级；
- 用户显式与 config forwarding。

sgpt controlled options：

```text
RequestTTY=force
ExitOnForwardFailure=yes
RemoteCommand=none
SessionType=default
StdinNull=no
ForkAfterAuthentication=no
ClearAllForwardings=no
```

用户 argv parser 只处理 sgpt 必需的 option arity、destination 和 remote command 约束。以下模式被拒绝，包括 attached forms：

```text
-T -N -n -f -s -W -G -V -Q -O
```

允许 attached/separated `-p/-L/-R/-D/-J/-i/-o`。非 ASCII 或非法 option 返回校验错误，不能 panic。附加远端命令被拒绝。

Forwarding conflict 只解析 `ssh -G` 的规范化行：

- `localforward`、`dynamicforward`、`remoteforward` 检查 listener endpoint；
- TCP listener port 等于 `SGPT_PORT` 时拒绝，不区分 bind address；
- target 使用 `SGPT_PORT` 不冲突；
- listener port `0` 和 Unix socket listener 允许。

Preflight 通过后，最终 SSH invocation 加入 sgpt 自己的受控 reverse forwarding。`ExitOnForwardFailure=yes` 让真实 forwarding 建立失败由 OpenSSH 明确报告。sgpt 不对任意 SSH 非零退出追加猜测性 forwarding 错误。

退出状态：

- SSH `0` → sgpt `0`；
- SSH 具体非零状态 → 原样传播；
- 被信号终止或无状态码 → `255`；
- sgpt 配置、preflight、relay 或 spawn 错误 → `1`。

## 资源限制

| 资源 | 限制 |
| --- | --- |
| stdin | `512 KiB`，在 `524289` 字节处停止并失败。 |
| 近期 Turns | 最多 10 个，软预算 `200 KiB`。 |
| Input Anchors | 最多 10 个，总软预算 `150 KiB`。 |
| Provider Request JSON | `1 MiB`，按实际 serialized bytes。 |
| Provider HTTP response | `2 MiB`，流式累计；成功和错误响应相同。 |
| assistant text | `512 KiB` UTF-8。 |
| Conversation logical content | 高水位 `2 MiB`，低水位约 `1.5 MiB`。 |
| history JSONL | 物理安全上限 `16 MiB`。 |
| Relay Ask body | `4 MiB`。 |
| Relay Prepare body | `512 KiB`。 |
| Relay control body | `64 KiB`。 |
| `ssh -G` stdout | `256 KiB`。 |
| `ssh -G` stderr | `256 KiB`。 |
| Pending Session TTL | 60 秒。 |
| Provider timeout | `1..=600` 秒，默认 60。 |

Provider response 同时支持 `Content-Length` 提前拒绝和无长度/chunked body 的读取中累计限制。`ssh -G` stdout/stderr 并发读取；任一超限都会终止并回收 child process。

## 测试策略与 seam

原则：

- 测试可观察行为，不锁定私有 helper、map、guard、request representation 或脚本 substring。
- 只在外部系统 seam 使用 fake：HTTP Provider、文件系统、时间、SSH executable、relay endpoint、shell executable。
- 不 mock Conversation、request builder、Projection Tree state 或 persistence algorithm。
- 错误路径同时断言副作用没有发生。
- 并发使用 barrier/channel 或显式状态操作，不依赖真实 sleep。

### Conversation tests

验证完整 Turn commit、idempotency、逻辑/外部压缩、Anchor count/bytes/truncation/order 和历史 Anchor normalization，不涉及文件或 HTTP。

### Local Shell Session tests

通过 `LocalShellSession::execute` 和真实本地 fake HTTP Provider 验证：

- new 成功后才建立 current；
- continue 保持 Conversation ID；
- Provider、commit、persistence failure 不返回 answer且状态不变；
- lock 覆盖 Provider 调用和 persistence；
- version 1 在成功 continue 时迁移。

文件 adapter 使用真实临时目录验证 v1/v2、权限、原始文件失败不变、append/atomic rewrite 和 physical compaction。

### Provider tests

捕获真实 HTTP request JSON，验证 message sequence、调用次数、JSON escaping、UTF-8、精确 1 MiB 边界、chunked/error response 和 2 MiB 读取限制。

### Projection Tree 与 relay tests

状态 module tests 通过 interface 验证 lifecycle、membership、lease、stale cancellation、Conversation isolation、idempotency、expiry 和 Session limit。Router tests 只验证鉴权、JSON、route body limit、HTTP status/text mapping 和 Provider 是否被调用。

### Bootstrap 与 SSH tests

- generated bootstrap 通过 `/bin/sh -n`。
- 真实 `/bin/sh` + 受控 PATH + fake curl/ssh/shell executables 验证 activate、ask、retry、unregister、nested preparation 和 cleanup。
- Rust policy 和 shell adapter 使用同一个 fixture table。
- fake `ssh` 分别捕获 `ssh -G` 和 final invocation。
- stdout/stderr 超限测试验证 child 被回收。
- macOS 上使用 pseudo-terminal 运行交互式 Bash，验证 nested preflight 不输出 `[1]`/`Done` job notifications。
- Tunnel binary integration 验证 SSH exit status、spawn failure、relay listener cleanup 和远端错误不被误报为 forwarding failure。

## 手工 smoke checklist

自动测试无法完全替代真实 Provider、多 Shell 和多主机 SSH。发布前执行：

1. 本地 new、continue、stdin-only、args + stdin。
2. Provider 或 persistence failure 时 stdout 为空，current 不变。
3. stdin/request/response 超限时快速失败。
4. Bash、Zsh、Fish 各建立一个 Projected Shell Session，验证 PATH、locale 和用户启动配置。
5. 本机 → A → B，确认只有一个 Origin Relay。
6. A/B 分别 new/continue，Conversation 独立；B 退出不影响 A。
7. 同一 Projected Shell Session 并发被拒绝，不同 Sessions 可并发。
8. Nested Tunnel 登录成功时不出现 `[1]`/`Done` job-control 通知。
9. `Host`、`Match`、`Include` 和用户 forwarding 保留。
10. `SGPT_PORT` listener conflict 被拒绝；target 使用相同端口、port 0 和 Unix socket 可用。
11. `-G/-V/-Q/-O` 和附加远端命令被拒绝。
12. SSH 非零退出码保真传播，远端依赖错误不被误报为 forwarding failure。
13. Pending Session 在 60 秒后释放；正常退出执行 unregister。
14. 0.5.x version 1 history 首次成功写入后原子迁移。
15. 长 Conversation 经逻辑或物理压缩后仍能继续。

## 升级与兼容性

- Cargo package version 为 `0.6.0`。
- 本地 version 1 history 自动迁移为 version 2。
- 0.5.x relay protocol 不兼容；旧 Tunnel 必须退出并重建。
- bootstrap 在建立 Projected Shell Session 时注入，升级 binary 或修改 bootstrap 后，已运行的 Projection Tree不会热更新；必须退出整棵 tree，并从本机重新执行根 `sgpt tunnel ssh`。
- Projected Conversations 是临时状态，不跨 Origin Relay 重启或 Tunnel 重连保留。
- 正式支持 Linux/macOS 和 `/bin/sh`、bash、zsh、fish；BusyBox best-effort，原生 Windows Shell 不支持。
